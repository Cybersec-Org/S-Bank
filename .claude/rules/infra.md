# Infrastructure and CI rules

## Containers and Compose

- Pin every image to an exact version tag (`postgres:18.x-alpine`, `quay.io/keycloak/keycloak:26.x.y`); digests are better for CI. Never `latest`. Dependabot (`docker`, `docker-compose`) keeps them current.
- Dockerfiles: multi-stage, minimal runtime image, `USER` non-root, `HEALTHCHECK`, no secrets in `ARG`/`ENV`/layers, `pnpm install --frozen-lockfile`, build context is the repository root (root `.dockerignore`).
- Two networks: `edge` (Caddy only) and `internal` (`internal: true`) for API, Keycloak, databases, SoftHSM, Mailpit. Only Caddy publishes ports; dev conveniences (Postgres, Mailpit UI) bind to `127.0.0.1` only.
- Every service has a healthcheck so `docker compose up --wait` works (CI and DAST rely on it).
- Secrets come from the root `.env` (generated by `node scripts/dev-secrets.mjs`, git-ignored) or Docker secrets. `.env.example` lists every variable with a placeholder or the `__GENERATE__` marker.
- Keycloak: realm as code in `infra/keycloak/` (exact redirect URIs, no wildcards, PKCE S256 required for the public client, brute-force detection on, password policy `length(12) and notUsername`, access token 5 min, refresh token rotation). Admin console is never routed by Caddy. `start-dev` only for local development.
- Caddy: TLS 1.2+ (prefer 1.3), HSTS, security headers, CSP for the web app, request size limits; `/partner/*` requires a client certificate from the S-Bank CA (`client_auth` mode `require_and_verify`) and forwards the certificate thumbprint in a header the API trusts only from Caddy.
- SoftHSM: token directory is a volume, never committed; keys are generated as non-extractable by a script.

## GitHub Actions

- Pin every action to a full commit SHA with the version in a comment (`uses: actions/checkout@<sha> # v7.0.1`). Tags are mutable — the March 2026 trivy-action incident force-pushed 75+ tags to malicious commits.
- Top-level `permissions: contents: read`; grant more per job only when needed (`security-events: write` for SARIF upload).
- `actions/checkout` with `persist-credentials: false`.
- Never use `pull_request_target` with a checkout of PR code; never interpolate `${{ github.event.* }}` untrusted fields directly into `run:` — pass them through `env:`.
- `step-security/harden-runner` first in every job.
- CI calls only the root scripts from AGENTS.md › Commands; if you rename a script, update the workflows in the same change.
- Required checks for `main`: `CI / ci-success` and `Security / security-gate`.
- Run `actionlint` and `zizmor` mentally or locally on every workflow change; the Security workflow runs them too.
