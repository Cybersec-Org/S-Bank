# Phase 2 — app blueprint (Expo)

## Create

1. `pnpm create expo-app app --template default` (confirm the current template name with `docs-researcher`; the default template includes Expo Router and TypeScript). Use `--no-install` and install from the root afterwards so the workspace lockfile is used.
2. Remove the template's example screens, components, hooks and assets you do not need (if a `reset-project` script exists, run it, then delete the script and its `package.json` entry).
3. Set `name: "@sbank/app"`, add scripts: `start`, `lint`, `typecheck`, `test`, `build`, `export:web`, `export:native`, `doctor`, `api:types`.
4. Move routes to `src/app` (supported by Expo Router) and configure the `@/*` path alias to `src/*`.
5. Install with `npx expo install`: `expo-auth-session`, `expo-web-browser`, `expo-secure-store`, `expo-local-authentication`, `expo-crypto` (if the auth session needs it), `@react-native-async-storage/async-storage` (preferences only). Regular deps: `@tanstack/react-query`, `openapi-fetch`, `zod`. Dev: `openapi-typescript`, `jest-expo`, `@testing-library/react-native`, `expo-doctor`. Camera, location, notifications and WebView are added later by their backlog items (B-23, B-30) — not now.

## `app.config.ts`

- `name: 'S-Bank'`, `slug: 'sbank'`, `scheme: 'sbank'`, `ios.bundleIdentifier` / `android.package`: `pl.sbank.app` (ask the user if they have a preferred id).
- `web.output: 'single'` (SPA) unless static rendering is needed; keep `bundler: 'metro'`.
- `experiments.typedRoutes: true`.
- No secrets. `extra` only for non-secret values; prefer `EXPO_PUBLIC_*`.
- Android: `allowBackup: false` (MASVS-STORAGE — no tokens in backups). iOS: no `NSAllowsArbitraryLoads`.

## Providers (`src/app/_layout.tsx` → `src/shared/AppProviders.tsx`)

`SafeAreaProvider` → `ThemeProvider` (tokens) → `QueryClientProvider` (defaults: `retry: 1`, `staleTime: 30s`, no persistence) → `SessionProvider` → error boundary with a Polish fallback.

## Session and roles (mock for now)

- `src/shared/auth/session-store.ts`: in-memory store `{ status: 'signedOut' | 'signedIn', principal?: { subject, displayName, roles: Role[], acr: '1' | '2' } }`. No tokens yet (B-10/B-14 add them).
- `roles.ts`: `type Role = 'customer' | 'employee' | 'admin'`, helpers `hasRole`.
- `secure-storage.ts` (native: `expo-secure-store` with `requireAuthentication: true`, `keychainAccessible: WHEN_UNLOCKED_THIS_DEVICE_ONLY`) and `secure-storage.web.ts` (in-memory Map). Same interface; unit-tested; not yet used for tokens.
- Mock login: on the start screen, in `mock` mode only, three buttons "Zaloguj jako klient / pracownik / administrator (MOCK)". In `live` mode the screen shows "Zaloguj się" (OIDC, B-10) and the mock buttons do not exist. A test asserts the switcher is not rendered in `live` mode.
- Root `_layout.tsx` uses `Stack.Protected` (or the current Expo Router equivalent) with `guard` per group: `(customer)` needs role customer, `(employee)` employee, `(admin)` admin; `pay/[requestId]` needs any signed-in customer. Comment: UI guard only — the API enforces access.

## Data layer

- `src/shared/api/client.ts`: `createClient<paths>()` from openapi-fetch, `baseUrl` from env, middleware that adds `Authorization` when a token exists (B-10) and maps RFC 9457 problems to `ApiProblem`.
- `src/shared/api/schema.d.ts`: generated by `app:api:types` from `api/openapi.json` (first run after phase 3; before that, create it by running the script once the API exists — do not hand-write it).
- `src/shared/api/repositories.ts`: builds the repository set for the current `EXPO_PUBLIC_API_MODE`.
- Each feature: `api/<feature>.repository.ts` (interface), `api/<feature>.mock.ts` (deterministic demo data, 300–600 ms delay, no real people), `api/<feature>.http.ts` (throws `NotImplementedYet` with the backlog id until the endpoint exists), `hooks/use<Thing>Query.ts`.

## Shared UI (neutral placeholder design)

- `theme.ts`: tokens for colour (neutral greys + one accent, light and dark), spacing scale (4-based), radii, typography scale, min touch target 44. Comment at top: placeholder tokens — the final design replaces only this file and the primitives.
- Primitives: `Screen` (safe area, scroll, title), `Text` (variants), `Button` (primary/secondary/destructive, loading, disabled), `Card`, `TextField` (label, error, hint), `MoneyText` (tabular numbers, grosze in), `ListItem`, `EmptyState`, `ErrorState` (retry), `LoadingState`, `MockBadge`, `PlaceholderBlock` (labelled grey box for not-yet-designed areas).
